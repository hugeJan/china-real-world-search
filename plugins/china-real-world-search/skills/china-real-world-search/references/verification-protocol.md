# Verification Protocol for Public-Service Claims

Use this protocol only for an in-scope government, public-institution, state public-service, or public-transport claim.

## 1. Write a falsifiable proposition

Rewrite the question as:

> **provider/service + requested action or state + jurisdiction + time**

Examples:

- `Can a non-local adult apply for service X in city Y today?`
- `Does branch X handle card replacement on Saturday?`
- `Is route X operating on date T?`
- `Was platform A only historical, or is its entry currently available?`

Do not convert the protocol into general company, product, technology, or investment research.

## 2. Split rule, execution, and channel claims

A single answer may contain different propositions:

- **rule** — eligibility, materials, fee, responsible authority;
- **execution** — current local procedure, opening hours, timetable, or disruption;
- **channel** — exact app, mini program, branch, counter, station, or provider;
- **compatibility** — whether the channel completes the target process;
- **relationship** — what official connection is established.

Verify each with the source that naturally generates it.

## 3. Minimal provenance record

For decisive evidence, track as applicable:

- original data-generating authority/operator/system;
- publisher/host;
- exact service or document name;
- jurisdiction;
- event/effective/publication/update date;
- retrieval time;
- operator/developer identity;
- current usability evidence;
- compatibility evidence;
- official-relationship evidence.

The purpose is to stop snippets, reposts, provider claims, and stale pages from masquerading as current origin evidence.

## 4. Time fields are not interchangeable

Distinguish:

- event time;
- document date;
- publication date;
- effective date;
- service update time;
- page last-modified time;
- repost time.

For current service questions, an old notice is historical unless present state is independently established.

## 5. Locality

Use the smallest jurisdiction that controls the service:

> **national/provincial rule → city/district implementation → exact outlet/channel/operator**

Do not replace the user's city with another city's easier-to-find process.

For routes and stations, resolve the exact origin, destination, station/campus/branch, and date.

## 6. Source independence

Two pages are not independent if both repeat one upstream record.

Common chains:

- official notice → media repost → public-account repost → search summary;
- operator notice → aggregator → forum screenshot;
- provider marketing → SEO article → self-media repost.

Prefer a second source generated by a different workflow when cross-verification matters.

## 7. Conflict resolution

When sources disagree, compare:

1. competent scope;
2. jurisdiction;
3. effective date;
4. rule vs execution;
5. current vs historical;
6. provider marketing vs target-process evidence;
7. official relationship vs practical compatibility;
8. original source vs repost.

Both of these can be true:

- `third-party channel works`;
- `no current official source designates it`.

Both of these can also be true:

- `full line plan has N stations`;
- `initial operating section currently has fewer`.

## 8. Negative-evidence diagnosis

Before saying a service/channel does not exist, test whether it is:

- app or mini-program only;
- login or real-name gated;
- moved, renamed, revised, or removed;
- unindexed;
- region/account dependent;
- blocked by CAPTCHA or access limits;
- absent from an official guide while a compatible third party still exists;
- hidden by incorrect official terminology.

`Not found` is not automatically `does not exist`.

## 9. Historical reconstruction

For an old or removed service entry:

1. find the original notice, PDF, or archived page;
2. record exactly what it proved and when;
3. search current migration, replacement, suspension, or restoration notices;
4. inspect current platform state only when accessible;
5. report historical and current status separately.

## 10. Government-domain authorship

Authority comes from who makes the statement, not merely the domain.

Separate:

- government-authored text;
- citizen-submitted wording;
- reposted material;
- quoted provider claims;
- an official response that does not address the provider.

## 11. Confidence language

Use precise language:

- **confirmed current** — direct current competent evidence;
- **cross-verified** — independent mechanisms support the same proposition;
- **recently evidenced** — current state was not directly inspected but recent evidence supports it;
- **historical only** — evidence proves a past state;
- **lead only** — unverified discovery clue;
- **unknown** — a material gap remains.

Do not use confidence wording to blur usability, compatibility, and official relationship.
